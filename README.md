## 1. 项目概述

### 1.1 项目定位

本项目构建一套便携式浅层地表油类泄漏检测系统，面向管道泄漏、地下储油设施渗漏等场景，实现非破坏性、非接触式的快速初步检测。系统基于扫频探地雷达（SFCW GPR）采集地下电磁反射数据，结合边缘 AI 推理，在 RK3568 嵌入式平台上实时运行。

### 1.2 检测原理

扫频雷达向地下发射 720MHz ~ 2500MHz 的电磁波，逐频率点扫描，在每个频率点测量反射信号的幅度和相位。油类（介电常数 εr ≈ 2~3）与含水土壤（εr ≈ 15~25）之间存在显著的介电常数差异，导致电磁波在界面处产生可检测的反射异常，同时油类对高频电磁波有选择性吸收，导致频谱重心向低频偏移。系统利用这两类物理特征实现检测。

### 1.3 两阶段架构的设计动机

单一模型容易将金属管线、石块等地物误判为油污，因为它们在 B-scan 图像上都表现为异常反射。本系统采用两阶段架构：

- **阶段一** 基于 B-scan 图像的形态纹理做快速筛查，标记疑似位置
- **阶段二** 基于原始频域数据的物理特征做独立验证，区分油类与地物

两条证据链相互约束，大幅降低误报率。

### 1.4 硬件参数

| 参数 | 规格 |
|------|------|
| 嵌入式平台 | 移远 QSM368ZP-WF（RK3568） |
| CPU | 四核 ARM Cortex-A55，主频 2.0GHz |
| NPU | 1 TOPS，支持 INT8 量化推理 |
| 雷达类型 | SFCW 扫频雷达 |
| 扫频范围 | 720MHz ~ 2500MHz |
| 扫描点数 | 每道 1024 个频率点（复数：幅度 + 相位） |
| 天线配置 | 收发分离，间距 0.1m，贴地滑动 |
| 有效检测深度 | 地表以下 0.2m ~ 1.5m（含水土壤条件） |

## 2. 系统架构

### 2.1 数据流总览

系统存在两条从源头完全独立的数据支路，绝对不能共用同一份预处理数据：

```
扫频雷达原始采集
        │
        ├─────────────────────────────────────────┐
        │                                         │
   【图像支路】                              【频域支路】
   可做归一化、增强                         严格保幅，禁止归一化
        │                                         │
   拼成 B-scan 图像                    保幅频域缓冲区（ring buffer）
        │                                         │
   阶段一推理                           阶段二特征提取
   （NPU）                              （CPU，< 1ms）
        │                                         │
        └──────────────┬──────────────────────────┘
                       │
                  融合告警判断
                       │
              热力图显示 + 告警等级输出
```

**频域支路的核心禁忌：**
- 禁止 AGC（自动增益控制）
- 禁止逐道标准化
- 禁止任何形式的幅度归一化

违反以上任何一条，阶段二的物理特征计算将完全失效。

### 2.2 完整处理流程

```
① 扫频雷达贴地扫描
   每个位置采集 1024 个频率点的复数数据（幅度 + 相位）

② 图像支路预处理
   → 背景去除（减去所有道均值）
   → 按列归一化
   → resize 到 224×224
   → 拼成 B-scan 灰度图

③ 阶段一推理（EfficientNet-Lite0 双头，NPU）
   → 滑动窗口扫描 B-scan（窗口宽 80 列，步长 20 列）
   → 每个窗口输出：头A 异常概率 P ∈ [0,1]，头B 类型 [油/管线/石块/背景]
   → 生成热力图叠加在 B-scan 上实时显示

④ 事件触发
   → 若最高概率 > 0.65，记录异常水平位置，触发阶段二

⑤ 阶段二验证（CPU）
   → 从保幅缓冲区截取 ROI 窗口 + 左右背景窗口
   → 计算频谱重心差值 Δfc
   → 计算高频能量比差值 ΔHFR
   → 规则判断输出物理证据结论

⑥ 融合判断
   → 综合阶段一概率、头B类型、阶段二结论、空间一致性
   → 输出最终告警等级

⑦ 结果输出
   → 热力图实时显示在屏幕
   → 告警等级标注（红/橙/蓝/绿）
   → 原始数据上传云端
```

### 2.3 告警等级

| 等级 | 触发条件 | 颜色 | 建议操作 |
|------|---------|------|---------|
| 高置信漏油 | 阶段一高概率 + 头B判油 + 阶段二支持 + 空间持续 | 红色 | 立即复核，准备取样 |
| 中置信漏油 | 阶段一高概率 + 阶段二弱支持 | 橙色 | 记录位置，后续复核 |
| 地物标注 | 阶段一高概率 + 头B判管线/石块 + 阶段二不支持 | 蓝色 | 记录为地物，继续扫描 |
| 待复核 | 阶段一高概率 + 阶段二不确定 | 黄色 | 人工判断 |
| 正常 | 阶段一低概率 | 绿色 | 继续扫描 |

### 3.3 沙箱实验方案（密封袋法）

**为什么用密封袋法而非真实污染：**

真实油类污染土壤后清理极为困难，且会对实验环境造成不可逆污染。密封袋法将油装在完全密封的容器中，GPR 感应的是容器内油类的介电特性，扫描完成后取出容器，土壤零污染。

**操作步骤：**

1. 准备含水砂壤土沙箱（含水量约 15%~20%）
2. 将食用油装入 PE 封口袋，排尽空气后密封
3. 分别测试两种尺寸（17×10.5cm，22×15cm）和两种放置方式（平放、竖放）
4. 在 4 个不同深度（20cm、50cm、90cm、130cm）各测试一组
5. 每组扫描完成后取出袋子，土壤恢复原状
6. 同时扫描不含袋子的纯背景区域作为对照

**沙箱实验数据的双重用途：**
- 作为模型训练数据的一部分（约 20% 比例），弥合仿真与真实的域偏差
- 用于阶段二阈值标定，计算真实条件下的 Δfc 和 ΔHFR 参考范围

**阶段二阈值标定流程：**

```
沙箱扫描（有袋 + 无袋各若干组）
         ↓
python calibration/sandbox_measure.py
（提取每组的 delta_fc 和 delta_HFR）
         ↓
python calibration/threshold_calibrate.py
（统计两组分布，选取最优分隔阈值）
         ↓
calibration/thresholds.json
（运行时读取，格式：{"threshold_fc": ..., "threshold_hfr": ...}）
```

**关键验收标准：** 运行 `threshold_calibrate.py` 后，有袋和无袋两组的 delta_fc 分布应有明显分离。如果两组分布完全重叠，说明特征区分度不够，需要重新检查雷达保幅采集设置。

## 4. 阶段一：B-scan 异常检测

### 4.1 模型架构

**主干网络：** EfficientNet-Lite0

EfficientNet-Lite 系列专为边缘 NPU 打造，去除了 SE 模块和 Swish 激活，改用 ReLU6，所有算子均为 RKNN NPU 原生支持，INT8 量化后模型约 1.5MB。

| 模型 | 参数量 | FLOPs | NPU 友好度 | 说明 |
|------|--------|-------|-----------|------|
| EfficientNet-Lite0（首选） | 4.7M | 0.39G | 高，无 SE/Swish | 默认选择 |
| GhostNet-0.5x（备选） | 2.6M | 0.042G | 高 | 算力极限时降级 |
| YOLOv8n（可选） | 3.2M | 8.7G | 高，官方 RKNN 支持 | 需要精确定位框时 |

**双头输出设计：**

在 GlobalAvgPool 输出（1280 维）后添加两个独立分支：

```
主干（EfficientNet-Lite0）
        ↓
  GlobalAvgPool (1280维)
        ↓
  ┌─────┴─────┐
  ↓           ↓
头A           头B
Linear(1280,1)  Linear(1280,5)
+ sigmoid       + softmax
  ↓               ↓
P(异常)         [P(油类), P(金属管线),
∈ [0,1]         P(非金属管), P(石块), P(背景)]
```

**损失函数：**
```
总损失 = 0.5 × BCELoss(头A) + 0.5 × CrossEntropyLoss(头B)
```

### 4.2 训练要点

**数据增强：**
- 随机水平翻转
- 随机亮度/对比度扰动（±20%）
- 高斯噪声添加（模拟真实采集噪声）
- 随机裁剪后 resize 回 224×224

**类别平衡：**
油类正样本数量通常少于背景负样本，在 CrossEntropyLoss 中对各类别加权，或对正样本做过采样。

**迁移学习策略：**
1. 加载 ImageNet 预训练权重
2. 冻结主干前 3/4 层，只训练后 1/4 层和两个头，训练 10 个 epoch
3. 解冻所有层，以较小学习率全量微调，训练 20 个 epoch

### 4.3 热力图生成

热力图将模型对每个扫描位置的打分转换为颜色，叠加在 B-scan 上：

```
B-scan 图像（H × W 灰度图）
        ↓
滑动窗口（宽 80 列，步长 20 列）
        ↓
每个窗口 → 模型推理 → 头A概率 p
        ↓
概率数组 [p1, p2, ..., pN]
        ↓
cv2.applyColorMap(COLORMAP_JET)    # 低→蓝，高→红
        ↓
cv2.addWeighted(alpha=0.6, beta=0.4)  # 半透明叠加
        ↓
最高概率位置绘制红色竖线 + 告警文字
```

**性能：**
- 单次推理（一个窗口）：约 10~20ms（NPU）
- 全幅 B-scan 处理：约 0.3s（21 次推理）
- 热力图渲染叠加：< 5ms（CPU）

### 4.4 空间一致性校验

真实油类泄漏在水平方向有面积扩散，管线等点状目标只产生短暂响应。维护长度 K=8 的环形缓冲区：

```
同时满足以下两条才升级为高置信告警：
  条件1（持续性）：最近 8 帧中头A概率 > 0.65 的帧数 ≥ 5
  条件2（类型一致性）：这些帧中头B=油类(index=0) 的比例 ≥ 0.6
```

此逻辑只需一个整数计数器和队列，CPU 微秒级完成，无需模型。

## 5. 阶段二：频域物理特征验证

### 5.1 设计原则

阶段二不做波形反演，不输出绝对电导率。它只回答一个问题：

> ROI 区域的频域特征，是否与「油类吸收高频电磁波」的物理规律一致？

**扫频雷达的天然优势：** 原始数据已经是频域，不需要 FFT，两个核心特征直接在原始幅度数据上计算。

### 5.2 原始数据格式

```
单道数据：shape = (1024,)，dtype = complex64
幅度：amplitude[f] = |complex[f]|
功率：power[f] = amplitude[f]²
频率轴：freq = linspace(720e6, 2500e6, 1024)   # 单位 Hz
```

### 5.3 三窗口截取

| 窗口 | 位置 | 道数 | 用途 |
|------|------|------|------|
| 左背景窗 | ROI 左侧 | 15 道 | 正常土壤参考频谱 |
| ROI 窗 | 异常中心 ±8 道 | 约 16 道 | 疑似异常区频谱 |
| 右背景窗 | ROI 右侧 | 15 道 | 正常土壤参考频谱 |

对每个窗口内所有道取均值，得到该窗口的代表性功率谱。背景基准 = (左背景 + 右背景) / 2。

### 5.4 特征一：频谱重心（fc）

**物理含义：** 各频率点的功率加权平均频率。油类吸收高频，重心向低频偏移。

```python
# 对每个窗口分别计算
power = amplitude ** 2                          # 每个频率点的功率
fc = sum(freq * power) / sum(power)             # 加权平均频率

# 计算差值
fc_background = (fc_left + fc_right) / 2
delta_fc = fc_ROI - fc_background
```

**判断方向：** delta_fc 为负值且绝对值大（典型值 < -100MHz）→ 高频被吸收 → 指向油类。管线/石块不改变频谱重心，delta_fc ≈ 0。

### 5.5 特征二：高频能量比（HFR）

**物理含义：** 高于 1600MHz 的能量占总能量的比例。油类选择性吸收高频，比值下降。

```python
HFR = sum(power[freq > 1600e6]) / sum(power)   # 高频能量占比

HFR_background = (HFR_left + HFR_right) / 2
delta_HFR = HFR_ROI - HFR_background
```

**判断方向：** delta_HFR 为负值且绝对值大（典型值 < -0.10）→ 高频能量减少 → 指向油类。

### 5.6 判断规则

```
从 calibration/thresholds.json 读取阈值

条件A：delta_fc < threshold_fc
条件B：delta_HFR < threshold_hfr

A AND B  →  结论 = "oil"    （物理证据强支持）
A XOR B  →  结论 = "weak"   （物理证据弱支持）
否则     →  结论 = "reject" （物理证据不支持）
```

### 5.7 嵌入式实现说明

阶段二所有计算均在 CPU 端完成，无需 NPU：

| 步骤 | 计算量 | 耗时 |
|------|--------|------|
| 幅度平方（功率） | 数组逐元素运算 | 微秒级 |
| 窗口内取均值 | 数组求均值 | 微秒级 |
| 频谱重心 | 加权求和 | 微秒级 |
| 高频能量比 | 数组切片求和 | 微秒级 |
| 差值与阈值比较 | 减法和比较 | 纳秒级 |
| **合计** | | **< 1ms** |

## 6. 融合告警逻辑

### 6.1 融合规则

```python
# 维护长度 8 的环形缓冲区
buffer = deque(maxlen=8)
# 每帧存储：(头A概率, 头B类型索引, 阶段二结论)
buffer.append((prob_a, type_b, stage2_result))

# 统计最近 8 帧
recent_high = sum(1 for p,_,_ in buffer if p > 0.65)
recent_oil  = sum(1 for p,t,_ in buffer if p > 0.65 and t == 0)

# 告警等级判断
if (prob_a > 0.85
    and stage2_result == "oil"
    and recent_high >= 5
    and recent_oil / max(recent_high, 1) >= 0.6):
    level = "high"       # 红色

elif prob_a > 0.65 and stage2_result == "weak":
    level = "medium"     # 橙色

elif (prob_a > 0.65
      and type_b in [1, 2, 3]          # 管线或石块
      and stage2_result == "reject"):
    level = "geo_object"  # 蓝色

else:
    level = "normal"      # 绿色
```

### 6.2 时序对齐要求

阶段一的图像支路和阶段二的频域支路必须对应同一段扫描数据。缓冲区管理需确保：阶段一分析第 N 帧图像时，阶段二读取的是同一段扫描的保幅频域数据，不能出现帧错位。

## 7. 嵌入式部署

### 7.1 模型转换流程

```
PC（PyTorch 训练）
    ↓
导出 ONNX（固定输入 224×224，batch_size=1）
    ↓
x86 Linux（RKNN-Toolkit2 转换）
    ↓
INT8 量化（需提供校准数据集，建议 200~500 张训练图像）
    ↓
生成 .rknn 文件
    ↓
复制到 RK3568 开发板
    ↓
RKNNLite API 加载 → NPU 推理
```

> **重要：** 模型转换必须在 x86_64 Linux 上执行，不支持在 ARM 开发板上直接转换。RKNN-Toolkit2 版本必须与板端 RKNN Runtime 版本严格对应，版本不匹配会导致模型加载失败。

### 7.2 标准化参数部署

阶段二的特征向量需要标准化，标准化参数在训练端计算，部署到板端复用：

```python
# 训练端（PC）
scaler = StandardScaler().fit(X_train)
np.save('scaler_mean.npy', scaler.mean_)
np.save('scaler_std.npy', scaler.scale_)

# 推理端（RK3568）
mean = np.load('scaler_mean.npy')
std  = np.load('scaler_std.npy')
x_norm = (x_raw - mean) / std
```

### 7.3 推理延迟参考

| 模块 | 输入 | 延迟 | 运行位置 |
|------|------|------|---------|
| EfficientNet-Lite0 双头 | 224×224 | 约 10~20ms/窗口 | NPU |
| 阶段二特征计算 | 三窗口频域数据 | < 1ms | CPU |
| 热力图生成叠加 | 全幅 B-scan | < 5ms | CPU |
| 空间一致性校验 | 8 帧缓冲区 | < 0.1ms | CPU |
| **全幅 B-scan 处理** | 21 次推理 | **约 0.3s** | NPU + CPU |

### 11.2 答辩技术逻辑

| 问题 | 回答要点 |
|------|---------|
| 为什么用扫频雷达 | 原始数据天然是频域，阶段二无需 FFT，直接利用，工程代价最低 |
| 为什么两阶段 | 图像快速筛查 + 物理特征验证，两条独立证据链降低误报率 |
| 为什么选 EfficientNet-Lite0 | 专为边缘 NPU 设计，无 SE/Swish，RKNN INT8 量化无障碍 |
| 为什么不直接测真实油污 | 密封袋法实现零污染测试，物理原理等效，更符合实验安全规范 |
| 为什么用含水土壤而非干沙 | 含水土壤与油类的介电常数对比度约 15，干沙仅约 1.5，区分度相差一个数量级 |
| 端云协同的意义 | 嵌入式端实时初判（< 0.5s），云端做离线深度分析，合理分配算力 |
